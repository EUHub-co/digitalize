# EUHub AI SEO / GEO / AEO 10-of-10 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Raise ai.euhub.co from SEO 7/10, GEO 6/10 and AEO 6/10 to an evidence-backed 10/10 standard by making every strategic page indexable, fast, expert-authored, source-cited, answer-ready and measurably visible in traditional and generative search.

**Architecture:** Keep the Next.js 16 App Router and three-locale `/en|/sk|/de` model. Separate reusable guide rendering, structured content and JSON-LD generation from page routes; add standalone proof and insight routes; statically prerender public marketing content; enforce quality with a production-server smoke test. External indexing, entity and measurement work runs beside the code stream and has its own acceptance gates.

**Tech Stack:** TypeScript, Next.js 16, React 19, JSON dictionaries, JSON-LD/schema.org, Node.js smoke tests, Google Search Console, Bing Webmaster Tools, IndexNow, PageSpeed Insights/Chrome UX Report and Umami.

**Spec:** `seo-audit-ai-euhub-co-2026-08-25.docx` and `seo-audit-ai-euhub-co-2026-08-25.pdf`

## Global Constraints

- Never fabricate a client, quote, credential, certification, metric, benchmark or outcome.
- Label modeled, projected and simulated numbers next to the number; never style them as delivered results.
- Obtain written client approval before publishing a name, logo, quote, architecture detail or attributable metric.
- Require subject-matter and legal review for EU AI Act, GDPR, SCC, security, data-location and contractual claims.
- Every JSON-LD claim must match visible page content; omit unsupported schema properties.
- Publish EN/SK/DE translations only after a fluent human reviewer approves meaning, terminology and citations.
- Preserve reciprocal EN/SK/DE/x-default hreflang, self-canonicals, one H1, accessible landmarks and non-empty image alt text.
- Treat `llms.txt` as optional discovery documentation, not a ranking mechanism; Google explicitly prioritizes normal SEO and unique people-first content over GEO hacks.
- Do not add FAQ, HowTo, QAPage or Speakable markup merely to chase a score. Add it only when the visible content and current search-engine guidelines support that type.
- A 10/10 is an operational standard, not a promise of ranking. Indexing, rich results, citations and AI visibility are never guaranteed by markup alone.
- Use `npm` for commands because the current implementation plans and scripts use it; do not regenerate the other lockfiles.
- Commit only the files named in each task; preserve unrelated worktree changes.

## 10/10 Exit Criteria

The project may claim 10/10 only when every gate below has fresh evidence.

| Dimension | Required evidence |
|---|---|
| SEO technical | 100% of strategic URLs return 200; root/legacy redirects are permanent; every page has unique metadata, one H1, correct canonical/hreflang/lang, valid JSON-LD, no broken internal links, and no accidental noindex. |
| SEO indexation | Search Console property is verified; sitemap status is Success; at least 90% of submitted strategic URLs are indexed or each excluded URL has an accepted reason; all three language families appear in URL Inspection. |
| SEO performance | At least 75% of page groups pass field Core Web Vitals after enough CrUX data exists; lab budgets are LCP ≤2.5s, INP ≤200ms and CLS ≤0.1 at the 75th percentile target. |
| SEO content | No strategic page is thin: service/compliance pages contain 700–1,200 useful words and pillar insights 1,200–2,000, with no padding or duplicate translation artifacts. |
| GEO authority | Every high-stakes guide has full author/reviewer identity, credentials, visible reviewed/updated date, primary-source citations, Organization/Person/Article relationships and a documented editorial policy. |
| GEO originality | At least three standalone case studies or evidence notes contain approved first-party methodology, measured outcomes or clearly labeled qualitative evidence. |
| GEO entity | Organization schema has legal identity, address, contact, logo and real sameAs profiles; leadership profiles use full public names and stable profile URLs; external profiles link back consistently. |
| GEO visibility | A monthly prompt set across Google AI features, ChatGPT Search, Perplexity and Gemini records citations/mentions for target topics; baseline and trend are stored without claiming causality. |
| AEO content | Each strategic topic has direct 40–60-word answers, natural-language questions, meaningful lists and at least one decision/comparison table where a table is genuinely useful. |
| AEO validation | Visible Q&A and structured data match exactly; Rich Results Test/schema validation has no errors; snippet/answer targets are tracked in Search Console and the prompt benchmark. |
| Quality system | `npm run lint`, `npm run build` and `npm run seo:smoke` pass; production post-deploy checks pass for EN/SK/DE; no audit assertion depends on an unverified local assumption. |

```tsx
const LOCALES = ['en', 'sk', 'de'] as const

export function generateStaticParams() {
  return LOCALES.map((lang) => ({ lang }))
}

export const dynamicParams = false

export default async function LocaleLayout({ children, params }: {
  children: React.ReactNode
  params: Promise<{ lang: string }>
}) {
  const { lang } = await params
  return (
    <html lang={LOCALES.includes(lang as (typeof LOCALES)[number]) ? lang : 'en'} suppressHydrationWarning>
      <body>{children}</body>
    </html>
  )
}
```
